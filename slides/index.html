Agents

kagent: agents as Kubernetes resources

An agent is just a resource


apiVersion: kagent.dev/v1alpha2
kind: Agent
metadata:
  name: cluster-reader
spec:
  description: Looks at the cluster (read-only) and reports what it finds.
  declarative:
    modelConfig: default-model-config      # LLM calls: via the gateway
    systemMessage: |
      You inspect a Kubernetes cluster with read-only tools ...
    tools:
      - type: McpServer
        mcpServer:
          name: tools-as-kagent            # tool calls: via the gateway too
          toolNames: [k8s_get_resources, k8s_describe_resource]
kagent turns this into a running agent: a Deployment, an A2A endpoint, a page in its UI. A prompt, a model, a list of tools. Lives in git like everything else.

DEMO
./scripts/demo.sh escapethe fixer's key: roll back yes, delete no
./scripts/demo.sh flooda tool call in a loop: refused after 30/min
escape sends tool calls with the fixer's key, the way the agent would. The delete gets "Unknown tool": the gateway doesn't even show the tool to that agent. flood: an agent stuck in a loop. Each agent has a request budget on its tools; over it, the tool never runs. Show the dashboard's MCP row afterwards. Don't run fix within a minute of flood.

Layers of control

The prompt — "please stay in playground"
a request
The gateway — which models, budgets, which tools
enforced
Kubernetes RBAC — where it may act
enforced

Today the gateway limits which tools. Limiting where is RBAC: the next step.

Be honest here: the fixer could still roll back a deployment in another namespace. The tool server runs with broad rights. The fix is boring: RBAC, a Role in one namespace. Same lesson as always: don't trust the prompt, enforce it in the platform.

Lessons learned

  • Small models need examples in the prompt to call tools right
  • Give agents simple actions: roll back, not "write a patch"
  • Agents need their own budget
  • Watch what agents do, not only what they say
7B model: sent a tool argument as the wrong type 9 out of 10 times; one example string fixed it. Patching: broken JSON. Rolling back: no JSON to write. Llama Guard first blocked the agent's own replies; now it only checks what the user sent.
